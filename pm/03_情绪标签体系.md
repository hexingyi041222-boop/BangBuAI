# 邦布情绪标签体系

> 用途：为情绪记录、S5 一日交互情绪总结、S6 异常情绪跟进定义统一的标签语义和数据边界。
>
> 定位：标签是基于本次获准输入生成的辅助判断，不代表用户真实、稳定或完整的心理状态，更不是心理健康诊断。

## 1. 设计原则与范围

1. **描述表达，不定义用户。** 标签描述某段输入中可观察到的情绪表达，不推断人格、病因、心理障碍或未来行为。
2. **当前情绪与事件时间分离。** 用户讲述过去、转述他人、假设未来或引用歌词，不自动等同于用户此刻的情绪。
3. **无标签不等于中性。** 输入缺失、证据不足、模型无结果和服务异常均须保留独立状态，不得折算为“平静”或“正常”。
4. **用户表述优先于模型推断。** 用户主动补记或纠正需明确标注为用户来源，不与 AI 估计混成同一事实。
5. **异常信号与临床判断分离。** “异常”仅指产品需要谨慎记录、适度跟进或按已批准流程转交的信号，不表示用户患病或处于某种医学状态。
6. **只处理有权限的数据。** 只基于当前获准处理的语音转写、文字和被授权的相关上下文；不默认读取其他 Session 的历史对话。

## 2. 标签维度

| 维度 | 建议字段 / 取值 | 说明 |
| :-- | --- | --- |
| 情绪类别 | 一个或多个 `emotion_code` | 采用有限、可解释的业务词表；允许无标签。复合感受可多标签，不强行归入单一类别。 |
| 来源 | `source_type` | `ai_inferred` / `user_reported` / `user_corrected`。来源始终与标签一起展示和统计。 |
| 时间指向 | `temporal_reference` | `current` / `past` / `future` / `habitual` / `hypothetical` / `quoted` / `unclear`。与事件发生时间分开存储。 |
| 强度 | `intensity`: `low` / `medium` / `high` / `unknown` | 是表达强度的粗粒度描述，不等同风险等级；阈值和标注方法须经评测校准。 |
| 证据质量 | `evidence_status` | `sufficient` / `insufficient` / `ambiguous` / `missing`。表明输入能否支持本次推断。 |
| 推断状态 | `result_status` | `ok` / `uncertain` / `insufficient_evidence` / `no_result` / `failed` / `declined`。不得用空数组掩盖状态差异。 |

强度允许为未知。模型给出的分值若未校准，只能标为原始分数或不确定性信号，不能解释为“有 X% 概率”或识别准确率。

## 3. 标签分类与定义

### 3.1 基础情绪

| 标签代码 | 展示语义 | 定义及边界 |
| --- | --- | --- |
| `joy` | 愉快 / 喜悦 | 表达开心、满足、兴奋等正向感受；不推断其持续时间。 |
| `sadness` | 难过 / 失落 | 表达悲伤、失望、失落等负向感受；本身不是异常或风险结论。 |
| `anger` | 生气 / 愤怒 | 表达恼火、愤怒或受挫；不推断攻击意图。 |
| `fear_anxiety` | 害怕 / 焦虑 | 表达担忧、紧张、害怕或不确定；不得据此诊断焦虑障碍。 |
| `disgust_aversion` | 反感 / 厌恶 | 对某事表达排斥、不适或厌恶；不作道德评价。 |
| `surprise` | 惊讶 | 对未预期事件表达惊讶，可正向或负向，效价按证据独立记录。 |
| `calm` | 平静 | 输入明确表达平静、放松等状态时才可使用；没有识别结果不能自动标为平静。 |

### 3.2 复合情绪

复合情绪允许由两个或多个基础标签共同表达；下列常见组合可以提供可读别名，但不要求模型只能从中选择：

| 组合代码（可选） | 含义 | 例示边界 |
| --- | --- | --- |
| `bittersweet` | 喜悦与失落并存 | 告别、毕业等回忆可能有复合感受，但先判定时间指向。 |
| `relief_with_worry` | 放松 / 庆幸中仍有担忧 | 不将“还有点担心”压成单一正向情绪。 |
| `anger_with_sadness` | 愤怒与难过并存 | 保留多标签，不把愤怒推断为冲突或危险行为。 |
| `loneliness_with_longing` | 孤独与想念并存 | 只记录用户表达，不推断其社会关系质量。 |
| `gratitude_with_moving` | 感激与感动并存 | 需有相应语义证据；不得从礼貌用语直接推断。 |

实现上优先存基础标签数组及主次顺序；组合代码是可选展示层映射，避免因组合数量膨胀而改变底层口径。多个标签冲突或证据不足时，返回 `uncertain`，不强行选一个。

### 3.3 异常情绪与安全信号

此类标签是后端流程标记，不与基础 / 复合情绪互斥，也不表示医学意义的“异常”。普通情绪标签不能单独触发高风险流程。

| 信号代码 | 含义 | 使用边界 |
| --- | --- | --- |
| `self_harm_or_suicide_expression` | 出现直接自伤 / 自杀意念表达 | 属独立安全信号，不是情绪类别或诊断；依据获批的 BB-SAF-001 流程处理。 |
| `life_safety_concern` | 出现可能涉及生命安全的间接表达 | 必须结合上下文、时间指向和澄清结果；不能只靠关键词定级。 |

PRD 列出直接自伤 / 自杀表达、间接生命安全风险表达、以及“连续 3 天被标记为异常情绪”作为 V1.0 初始信号，其中持续天数和分级阈值明确待安全 / 合规评审校准。

## 4. 生成与落库链路

```text
用户主动发起语音 / 文字交互
        ↓ 先校验授权、用户/设备绑定、输入关联和时间信息
硬件采集音频或 App 接收文字
        ↓ 音频只用于当次云端 ASR；转写 / 文本标记来源、完整性和时间
AI 网关调用云端模型进行语义与情绪辅助识别
        ↓ 输出候选标签、证据范围、时间指向、置信度和结果状态
AI 网关校验 Schema、安全规则与不确定性
        ├─ 可支持的结果 → 作为辅助标签返回
        ├─ 不确定 / 证据不足 → 中性澄清或明确提示信息不足
        ├─ 无结果 / 服务异常 → 保留状态，不构造情绪标签
        └─ 命中待评审的安全信号 → 进入获批安全分流，不由情绪标签自行定级
        ↓ 结果携带 trace_id、请求/交互关联、模型/规则版本和授权用户
业务后端执行权限、幂等、字段与状态校验
        ↓ 区分 AI 估计、用户补记/纠正及未完成结果
后端持久化获准的情绪记录与异常跟进记录
        ├─ 当日授权记录 → S5 汇总
        └─ 需要跨 Session 跟进的异常记录 → 下一次用户主动交互时按需查询
```

**链路约束：**

- AI 在云端提供辅助识别；AI 网关负责结构化与内容安全，业务后端是记录和业务状态的权威端。模型结果不是授权、人工处理结论或用户真实状态的事实断言。
-  ASR处理后不持久化；TTS 音频播完销毁。对话文字和情绪标签按授权及已告知用途由业务后端保存；不默认用于模型训练。
- 每条结果关联用户、设备、请求 / 事件、交互 / Session、来源端、事件发生时间及服务端接收时间。重复请求、补传和重试按事件身份幂等处理。
- 用户纠正、补记和 AI 推断分开存储。AI 结果与用户补记冲突时，不用时间戳静默覆盖；展示与统计优先级及更正规则需经产品、后端和合规批准。

## 5. 置信度、不确定性与误判处理

PRD 未定义置信度阈值，并明确未校准分值不得当作准确率。上线前由 AI 工程提供置信度语义、校准 / 评测结果、模型版本及阈值配置；阈值须经产品、安全和合规评审。阈值未定或模型不支持可靠置信度时，采用保守状态，不输出确定性标签。

| 情况 | 标签记录方式 | 面向用户与后续处理 |
| --- | --- | --- |
| 有充分、当前且可关联的证据 | `result_status=ok`，保存标签及证据引用 | 以可能性 / 观察式表达，不断言。 |
| 分数低于经评审阈值，或标签冲突 | `result_status=uncertain`；可记录候选和分数，但候选不得计入确定曲线 | 可问“我不确定有没有理解对，你现在更接近哪种感受？”；允许跳过、纠正或结束。 |
| 输入过短、缺失、截断、转写不完整或证据不足 | `result_status=insufficient_evidence`，`evidence_status=insufficient` | 不列入情绪曲线范围内，不参与完整情绪曲线或总结。 |
| 模型未返回标签 / 无法理解输入 | `result_status=no_result`，标签为空并记录空结果原因 | 不列入情绪曲线范围内，不参与完整情绪曲线或总结。 |
| 超时、API 错误、网络不可用 | `result_status=failed`，记录错误类型和时间 | 走服务兜底；不声称已完成识别，不做端侧离线推理。 |
| 用户拒绝、退出或不愿回答 | `result_status=declined`，停止当前情绪追问 | 尊重拒绝，不以持续关心为由继续追问。 |
| 安全信号不确定 | 情绪结果仍为 `uncertain` / `insufficient_evidence`；安全流程另记 `review_pending` 或经批准的路由状态 | 不下诊断，也不能据不确定标签宣称“没有风险”；按经评审流程澄清或转人工。 |

### 5.1 处理“词汇谬误”与时间错配

模型必须识别情绪归属对象、说话人及事件时间，不可仅凭负向词汇分类当前情绪。至少检查：

1. **时间表达：**“去年很难过”标为 `past`，不能直接作为今天的 `sadness`；只有用户明确表示回忆当前仍令其难过时，才可分别记录“过去事件”和“当前感受”。
2. **引用与转述：**“他说我很糟糕”不等于用户认同这句话；引用内容不作为用户当前情绪的充分证据。
3. **否定、反讽和假设：**“我并不害怕”“如果我失败了会很难过”等须保留否定 / 假设结构；无法稳定解析时设为 `unclear` 并返回不确定。
4. **主体区分：**用户在描述他人情绪时，不把他人的状态记录到当前用户名下。
5. **交互澄清：**时间或主体有歧义时使用中性问句，例如“你是在说当时的感受，还是现在也有类似感受？”用户不答即保留不确定，不反复追问。
6. **数据时间：**同时记录表达发生时间 `occurred_at` 与所述事件时间 `event_time`；不把回忆事件时间当作情绪标签写入日期的依据。

用户否认或纠正 AI 标签时，应停止坚持原判断，记录纠正来源并按批准规则更新展示 / 汇总；不得把原标签继续作为确认事实用于跟进。可将纠正样本作为隐私受控的 badcase 供排查，但不得因排查默认用于训练。

## 6. 标签生命周期与 S5 / S6 使用

### 6.1 单次记录

通过授权、关联及 Schema 校验后，后端保存符合留存政策的标签事件和处理状态；原始音频不持久化。可用标签、无结果、不确定、失败和拒绝都保留各自状态，便于解释覆盖范围和定位误判。

### 6.2 S5 一日交互情绪总结

- 按 PRD 以**北京时间自然日**划分统计窗口；迟到补传的数据归回其对应发生日期，不并入次日。事件发生时间与服务端接收时间均保留，时间不可信或无法确定归属日时标记为待核验，不静默猜测日期。
- 仅聚合该用户、该日、授权范围内、可追溯且有效的 `ok` 记录；该标签为对话结束之后才去分析这次对话中用户的情绪标签。
- 用户自述、用户纠正与 AI 推断分来源统计；不确定候选不计为确定情绪。不得把“无结果”或未交互的时间段填成平静、悲伤或任何情绪。
- 摘要须说明覆盖范围与数据不足；无记录时展示无记录 / 暂不可用，有部分记录时只概括实际记录。输入不足时不生成貌似完整的曲线，不补造事件、原因或情绪变化。
- S5 只归纳实际输入，不作心理健康诊断。生成与主动播报 / 打扰分开；不得因迟到补传而主动打扰用户。

**建议的窗口流程：**

```text
用户查看 S5 或达到已定义的总结触发条件
        ↓ 校验授权并读取当日可用事件
按 occurred_at 归日，核对 received_at、补传及去重状态
        ↓ 仅汇总有效、可追溯的标签；保留来源和不确定状态
数据充分？ ─ 否 → 展示已有记录 + 数据不足说明，不生成完整总结
    │ 是
    ↓
云端生成覆盖实际记录的摘要 → 后端校验证据范围、权限与安全边界 → 展示 / 按期销毁日报
```

### 6.3 异常信号与 S6 跟进

```text
当前 Session 出现需留意信号
        ↓ 按经评审阈值记录信号、最小必要原因、证据引用和状态
后端创建异常跟进记录（pending_followup）；不主动唤醒或打扰
        ↓ 下一次用户主动发起交互时，查询该用户对应的异常记录
AI 仅收到该条记录的必要摘要，不拼接其他历史对话
        ↓ 以自然、低压力方式适度询问一次
当前结果正常 → 回写正常结果并关闭普通异常跟踪
用户回避 / 否认 / 要求停止 → 停止追问并记录用户选择
仍不确定 / 服务失败 → 不标记为正常或已解决；保留实际状态，不自行重复触达
符合经评审高风险条件 → 独立进入 BB-SAF-001；跟进记录不等于人工已处理
```

后端接口须支持异常信号及对应原因的记录、按授权用户查询和跟进结果更新；查询请求关联用户、对应异常记录与当前 Session。仅查询需要跟进的对应记录，不默认读取或延续其他历史对话。用户回避时停止追问；高风险流程的必要上报仍严格按已告知且经评审的 BB-SAF-001 执行。记录留存期限、访问角色和审计要求待隐私 / 安全评审。

建议的跟进状态：`pending_followup`（待下次主动交互）、`in_followup`（本次已查询 / 询问）、`closed_normal`（检测正常并结束普通异常跟踪）、`stopped_by_user`（用户拒绝 / 要求停止）、`review_pending`（证据或服务不足，状态未定）、`safety_routed`（已路由安全流程）。`safety_routed` 不表示上报送达或人工完成。

## 7. 核心数据字段

| 字段 | 类型 / 示例 | 定义与规则 |
| --- | --- | --- |
| `emotion_event_id` | string | 标签事件唯一标识；重试 / 补传沿用同一事件身份以便幂等。 |
| `trace_id` | string | 串联用户输入、AI 网关、模型调用、后端写入及回执。 |
| `user_id`, `device_id` | string | 授权用户及目标设备；后端校验绑定关系，不信任未经验证的报文值。 |
| `request_id`, `interaction_id`, `session_id` | string | 关联请求、交互与当前 Session；不以 Session 关联代替读取其他历史对话授权。 |
| `source_type` | enum | `ai_inferred` / `user_reported` / `user_corrected`。 |
| `input_modality` | enum | `voice_transcript` / `text` / `manual_entry`；不在标签记录中持久化原始音频。 |
| `result_status` | enum | `ok` / `uncertain` / `insufficient_evidence` / `no_result` / `failed` / `declined`。 |
| `labels` | array | 每项包含 `emotion_code`、可选 `role`（primary / secondary）、`valence`、`arousal`、`intensity`；可为空但须结合 `result_status` 解读。 |
| `confidence` | object / null | 可含 `value`、`scale_type`（raw / calibrated）、`calibration_version`、`threshold_profile`；未校准分数不得当概率或准确率。 |
| `evidence_status` | enum | `sufficient` / `insufficient` / `ambiguous` / `missing`。 |
| `evidence_ref` | object / null | 指向最小必要的输入记录及文本片段范围 / 音频转写时间范围；优先引用，不复制敏感原文。 |
| `temporal_reference` | enum | `current` / `past` / `future` / `habitual` / `hypothetical` / `quoted` / `unclear`。 |
| `event_time` | ISO 8601 / null | 用户所述事件发生时间；与标签记录时间分开。 |
| `occurred_at`, `received_at` | ISO 8601 | 输入 / 事件发生时间与服务端接收时间，均含毫秒及显式时区；服务端时间用于对账。 |
| `model_version`, `prompt_version`, `taxonomy_version` | string | 支持结果追踪和版本化评测；具体命名与保存策略待工程确认。 |
| `risk_signal` | object / null | 安全信号类型、证据状态及获批路由状态；不得混入普通情绪标签或自行推导医学等级。 |
| `followup_record_id`, `followup_status` | string / enum | 关联异常跟进记录及当前业务状态；查询仅针对该用户对应记录。 |
| `user_correction_ref` | string / null | 关联用户否认、纠正、补记及展示状态，保留来源可区分性。 |
| `error_code`, `error_detail` | string / null | 记录 `failed` / `no_result` 原因；详情需去除不必要的敏感内容。 |

## 8. 合规红线与防伤害要求

- **不做心理诊断。** 不将标签表述为疾病、病理状态或专业评估；不诊断抑郁、焦虑、创伤等，不宣称已完成专业判断。标签和模型输出不作为临床诊断或唯一处置依据。
- **避免断言和贴标签伤害。** 对用户使用“听起来你可能……”等可纠正表达；不说“你患有……”“我知道你现在……”，不把单次识别固化为身份、人格或历史事实。
- **不以标签操纵关系或业务。** 不用负面标签制造依赖、诱导消费、延长使用或替代真实社交；异常跟进适度、可拒绝，不主动打扰。
- **尊重纠错、拒绝和退出。** 用户否认、纠正、拒绝澄清或结束互动时，不争辩、不持续追问；按产品规定提供记录管理 / 申诉能力。
- **高风险不静默降级。** AI 不确定时不诊断、不承诺安全，也不以“情绪正常”取代经评审的风险流程；按必要性、授权和最小范围转交人工，明确邦布是 AI 且不能替代专业帮助或紧急服务。不承诺保密、不提供危险细节。
- **数据最小化与目的限制。** 标签、证据和异常原因按授权用途处理、加密并限制访问；模型训练默认关闭，任何后续训练用途须另行满足法定条件 / 单独同意及隐私评审。高风险信息仅由授权系统按最小必要范围留存。
- **保护未成年人。** PRD 的 V1.0 范围不开放未成年人独立使用；年龄识别与拦截方案须完成评审，未满足前不启用对应服务。
